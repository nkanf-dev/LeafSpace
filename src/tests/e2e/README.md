# Browser acceptance tests

## Run

```sh
npm ci
npx playwright install --with-deps chromium firefox webkit
npm run test:e2e
```

Playwright builds the deployable bundle, then starts Vite preview on `127.0.0.1:4173` with a strict port. The production preview avoids dev-server dependency re-optimization and HMR reloads that can discard a currently open book. Both local runs and CI start their own preview server. An optional `PLAYWRIGHT_BASE_URL` skips server startup and targets a separately running application. `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` can select an existing Chromium binary. The normal default is Playwright's pinned browser.

## Coverage

- **Shell/import/recovery:** empty library, real PDF.js text/canvas rendering, malformed and empty PDF recovery
- **Reader:** page bounds, keyboard/range navigation, accessible zoom and mode controls, native keyboard button activation
- **Mouse pan:** rapid native movement retains the latest target across saved intermediate scroll frames, settles at measured bounds, and is repeated five times without retries in WebKit. Deterministic UI tests also cover release-time settling, authoritative external restoration during pending paint, clamped targets and integer-rounded offsets
- **Fit geometry:** the complete bordered paper has zero horizontal range at five widths and in five grid panes. Six projects exercise height-threshold transitions with 120-frame samples, requiring stable/visible final60-frame tails and decoded fixture colors after screenshots. Explicit vertical scroll space avoids custom-scrollbar width feedback; existing zoom/pinch/persistence checks retain their tolerances
- **Quick Flip:** selection without navigation, cancel/commit, repeat entry, held-arrow acceleration, Space autorepeat, focus containment/restore, holding and releasing preview pages
- **Thumbnail actions:** six-project touch-pointer contracts for Quick Flip and held-page sheets, original-release suppression, first-Escape/Tab ownership, pressed-versus-selected page, linked-window removal and focus recovery, breakpoint/rotation recovery, 320px and short-landscape layouts, native Enter/Space buttons, stacking hit targets and scoped accessibility checks. Chromium mobile/tablet also use native CDP touch for hold/release, interruption, fresh actions and scrolling
- **Workspace:** duplicate hold prevention, reference window opening/closing, independent navigation, dock/swap/float, remove-and-close, single-click focused-reader navigation, double-click comparison, Escape stack priority
- **Interrupted workspace input:** drag/resize/split cancellation unit contracts, native mouse drag followed by dispatched blur or keyboard Escape, reference-close focus across floating/split/grid layouts, and keyboard focus recovery after held-page cancellation/removal
- **Held metadata:** generated-book name/note editing, Unicode/IME event contracts, long unbroken names and scoped accessibility, saved reopen/default-name reset, cancellation before global reference/drawer Escape, cross-book draft isolation, unchanged saved reading scenes and original PDF-byte hashes. These contracts do not claim physical IME keyboard testing
- **Held-read intent:** slow recognized native mouse click sequences restore original main/reference pages and two-axis viewports before comparison; save/reload preserves the result. Native Enter/Space and compact click/touch paths remain distinct. Store tests permanently invalidate superseded intents, including navigation away and back
- **Completed reading flows:** 120-page nested outline, active-reference Quick Flip/TOC/timeline/page entry, 2–5-pane grids, repeated docking, capacity messages, reorder and explicit remove/close choices
- **Rendered viewport:** independent main/reference scale and two-axis scroll restoration, repeated fit-width reset, Ctrl-wheel paper-point anchoring
- **Mixed-page geometry:** a ten-page image-only fixture covers rotation, offset/rotated crop boxes, portrait/landscape/square and 6:1 tall/wide pages. Repeated toolbar zoom to 400% and a fresh zoom after scrolling deep into a tall page retain the same actual-canvas point within 2 CSS pixels, including fractional DPR. The maximum-size canvas is screen-captured before readback and its visible pixel is compared with the decoded canvas; cropped/rotated thumbnails, reference zoom/scroll, saved reopen and PDF-byte hashes are checked separately
- **Local PDF decoders:** a genuine small lossless JPEG2000 scan and identical RGB control require decoded red/green pixels in main/reference readers and Quick Flip/held thumbnails. Worker and main-thread thumbnail routes run separately, as do native WASM and forced local-JavaScript decoder fallback. Exact binary/license hashes, WASM magic, JavaScript MIME, app-base URL prefixes, saved reopen and original PDF hashes are checked
- **Page raster recovery:** controlled native canvas drawing failures require a visible, keyboard-reachable page-local Retry above real PDF text/link layers. Grab and text-selection modes, repeated explicit attempts, 10%/400% scale, a 320px short viewport, navigation away from failure and desktop background-reference ownership are covered. Recovery replaces only the failed Page canvas, retains its Document node and worker count, and checks saved reading state and original PDF-byte hashes
- **Internal PDF links:** numeric, named and indirect-reference destinations navigate the originating main/reference reader, including a destination already mounted in another pane. Native Enter retains arrow-reading continuity; same-page links retain their existing scoped scrolling and focus. A controlled native Worker message gate delays named resolution while focus moves to main or a newer toolbar control. Saved reopening, original PDF-byte hashes, retained Document DOM and worker counts, and external-link attributes are checked without following the external URL
- **Large raster PDF:** generated 106 MB image-only document, first-render timing evidence, final-page navigation, held thumbnail and IndexedDB reopen
- **Import recovery:** real opening-password rejection gives actionable local-copy guidance; owner-permission-only encryption still opens. Repeated failure resets the file input/import lock. Protected and corrupt replacements preserve PDF-byte hashes, held pages, independent scale/viewport and reference windows; recent-card recovery needs no original-file reimport
- **Activation identity:** repeated motionless reader clicks, stationary touch where supported, and toolbar focus do not rewrite the saved snapshot or its timestamp. Controlled page-clock checks retain a genuine page change’s original 500 ms save deadline. Real reference activation/Enter still save, while cancelled preview focus does not. These are operation counts and input contracts, not latency or battery benchmarks
- **Persistence:** manual and debounced saves, idle-save-loop regression, reload/recent restoration, two-document isolation, failed replacement recovery, immediate library and document-switch flushing, malformed/partial saved-state recovery, missing recent-file recovery
- **Cross-tab workspace protection:** two real pages share one isolated browser context and generated PDF. Paused page clocks and an explicit visible-lifecycle baseline establish a shared revision before divergent reading; stale automatic/manual/hidden saves and library exit retain the newer durable scene plus the stale tab's page, scale, held pages and reference window. Both load and overwrite confirmations bind to the displayed conflict revision: a competing commit keeps the local scene untouched and requires a fresh explicit decision, including after a failed reload read. Cancellation, reopened chosen scenes and unchanged PDF hashes run in desktop Chromium, Firefox and WebKit. The hidden case explicitly changes and dispatches visibility state: this is a lifecycle contract, not native tab-backgrounding or process-kill coverage. No application-store state is injected
- **Responsive conflict controls:** four focused cases use explicit 390×844 and 768×1024 viewports in the three desktop engine projects, without adding the larger concurrency suite to mobile projects. Real competing tabs establish distinct main/held pages and zoom, then verify Chinese alert/confirmation bounds, nested/document horizontal overflow, unobstructed fully visible buttons, actual dismissal/cancel/confirm clicks, exact unchanged durable records and native write counts. Load and overwrite each preserve the local scene until confirmation; viewport PNGs include both strips, cancellation and the chosen scene, with geometry JSON. These are responsive desktop-engine checks, not physical-device touch coverage
- **Recovery discoverability:** a persistent error-details action reopens dismissed restore/save/import guidance without invoking recovery or changing the saved workspace. Native Enter/Space/Tab focus, repeated blocked-library attempts, 320px full-width explanation, inset focus ring and scoped accessibility are checked across six projects; successful retry removes the action
- **Storage faults:** a failed PDF asset write cannot be masked by saving a small snapshot; retries preserve the original file and latest reading position. A failed snapshot read blocks implicit overwrite during library/import navigation, with keyboard-cancellable explicit replacement
- **Storage upgrades:** native v1 databases containing Blob or ArrayBuffer PDFs upgrade without moving/replacing assets; schema/metadata failures still allow intact PDFs to render, then saving recovers after retry. Warm save/recent refresh tests count zero PDF-value reads or writes at the IndexedDB API boundary. Legacy Blob coverage first performs a native PDF-byte round trip outside the app: only Linux WebKit’s exact known Blob-preparation `UnknownError`, with a successful ArrayBuffer control, marks that Blob migration case unavailable and attaches the diagnostic. Other engine/probe failures remain failures; bytes and all application recovery tests still run on WebKit
- **Responsive:** full touch-accessible workflow at desktop 1440×900, tablet 768×1024, and mobile 390×844, including horizontal overflow and in-viewport action checks

Every test gets an isolated browser context and real IndexedDB. Fixture imports use the real file input; tests do not inject application stores. IndexedDB is read for durable-save checkpoints. Three recovery tests deliberately replace or delete only their isolated synthetic-book records to simulate malformed snapshots, partial legacy data, and a missing local file. The single deliberate 1.5-second idle wait checks three autosave debounce periods for an unwanted write loop.

Storage-recovery tests inject a `QuotaExceededError` for PDF-asset writes or an `UnknownError` for workspace reads at the IndexedDB operation boundary, then restore the operation and verify recovery through real controls. This tests application error handling, not physical disk exhaustion or a browser's eviction policy.

Storage version 2 adds only `bookMetadata`; the existing `books` and `workspaces` records stay in place. Unit tests cover partial sidecars, atomic replacement rollback, old v1 writers reopening after versionchange, malformed metadata, source/backfill races, and read-only dynamic-schema fallback after an aborted upgrade. Recents inspect all lightweight legacy keys and metadata, then read only selected cold/stale payloads. Warm synthetic three-book saves went from 20 MiB of PDF-value reads plus 5 MiB written to zero PDF-value I/O; these are operation counts, not browser latency/heap benchmarks. Recency reconciliation chooses the latest valid timestamp. Legacy rewrites that retain the identical source timestamp have no index revision signal; an explicit file open refreshes that metadata. No blanket cross-version or clock-rollback coherence is claimed.

Native reverse/forward Tab traversal and visible focus are asserted on all three engines. A standalone WebKit SVG hit-target probe documents the browser's clicked-descendant behavior; decorative SVGs are non-interactive so button clicks preserve normal keyboard navigation.

## Evidence

The responsive workflow attaches PNGs for welcome, reader, keyboard focus, Quick Flip, held pages, and comparison; the invalid-import test attaches the error state. Open `playwright-report/index.html` after a run. Failure screenshots and traces are retained automatically. These captures are review evidence, not pixel-golden tests.

The fixture generator is documented in `../fixtures/README.md`. Browser execution remains necessary: `playwright test --list`, lint, TypeScript checks, and UI/unit tests cannot establish that these real browser cases passed. Projects cover Chromium, Firefox and WebKit, plus Chromium tablet/mobile viewports. A dedicated mobile case opens and restores five reachable window tabs. Real iOS devices and full storage-exhaustion scenarios require separate coverage. Password coverage uses small synthetic legacy-encryption controls, not every PDF encryption variant. The generated 106 MB scan is an automated capacity regression, not a benchmark claim for arbitrary books or devices.

Storage-failure render checks compare actual decoded fixture pixels, retain a full native canvas bitmap, and capture the screen before readback so instrumentation cannot hide a malformed first paint. They also exercise native text selection. WebKit repeats the schema-failure case five times without retries alongside input stability tests. The reader initializes PDF.js's preferred readback-friendly 2D context before React-PDF's first drawing call; browser context attributes and 106 MB scan timings remain in the evidence.

Document-retirement coverage counts native Worker creation/termination through repeated saved-book library/reopen cycles, both with normal thumbnail workers and forced main-thread fallback. A parked custom-worker request is closed before initialization completes; the test deliberately waits 2 seconds to outlast its 1800 ms timeout and verify obsolete work does not start a fallback parser. These are lifecycle/operation checks, not browser heap measurements. Unit tests separately control pending parse/getPage/render/blob/disposal stages and same-book stale callbacks. Real pending PDF.js worker teardown remains a separate limitation.

Quick Flip's native Escape test checks a moved preview, released-input settling/stability, unchanged reading position and restored focus. It does not assume that Playwright's sequential native keydown/keyup protocol calls always complete within the application's short-tap threshold. Deterministic fake-timer UI coverage separately requires exactly one step per released short tap and no movement after release. Firefox repeats native cancellation and held-release scenarios without retries.


Browser-exit coverage checks native beforeunload dialogs with real user activation in desktop Chromium, Firefox and WebKit: cancelling a reload keeps an unsaved revision, explicit acceptance permits leaving, and confirmed saving removes the warning. It also covers a dismissed PDF-quota alert and untouched failed restoration versus new reading edits. A clock installed before navigation pauses page timing only after rendering and a confirmed save, keeping the unsaved interval deterministic; it resumes before render/save verification. Synthetic storage faults remain scoped to isolated fixture databases.

Exit ownership is ephemeral: a document-opening session token, comparison baseline, unconfirmed save owner and pending-PDF owner are not written to the saved schema. Unit/UI tests cover queued writes, same-fingerprint reopening, exact source ownership, null/partially failed restoration, error dismissal and StrictMode listener cleanup. A null restoration retry does not certify later reading edits as saved. Successful older queued writes may update the durable comparison, but cannot clear a newer save request's warning.

The exit guard only warns; it does not save during beforeunload. Separately, eligible pending reading changes attempt autosave at visibilitychange to hidden, without waiting for the visible 500 ms debounce. A live document/session and import/restore/error check precedes the same serialized save path. Hidden-save tests freeze page timers, dispatch a controlled visibility transition while keeping the runtime alive, wait for real IndexedDB completion, and reopen the saved book across six projects. They also cover failed writes, dismissed alerts, and unread snapshots. This is application event-contract coverage, not native OS backgrounding or a process-kill durability guarantee. Hidden saving does not retry failed storage, cancel retired queued disk writes, or reset a bfcache page. Browser-controlled dialogs need prior interaction and may be absent on mobile process termination; the listener exists only while this session has unconfirmed data or new reading state. See [MDN beforeunload guidance](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event).

Zoom precision UI tests separately control integer scroll quantization, fractional-DPR raster/display ratios, moving pinch midpoints, clamped-axis reversal, undelivered scroll, pan/touch starts, authoritative restores and precommit-stale completion callbacks. The reader retains an unrounded normalized paper point only across uninterrupted same-pivot zooms. Reserved interior geometry is applied synchronously; the current completed canvas supplies a guarded final correction. Both provisional and final writes persist only the actual browser-accepted offsets. This does not change PDF rendering resolution or claim physical iOS canvas-limit coverage.

Decoder tests install an off-origin HTTP(S) route blocker and verify actual decoder resources against the same-origin app prefix. Worker Resource Timing covers Firefox imports omitted by Playwright network events. This establishes local JPEG2000 decoder loading, not general network isolation, zero attempted external requests, font/CMap offline support, or cold-start offline availability. The app has no service worker/offline cache. Vite copies the exact installed PDF.js decoder directory and license notices into a versioned same-origin asset directory during configuration. The custom thumbnail worker uses a DOM-free WASM fetch factory and OffscreenCanvas-backed temporary canvases for image downscaling while keeping its existing fake-worker mode and `useWorkerFetch:false`. QCMS/ICC behavior is unchanged.

For a non-root decoder check, build and preview with `npx vite build --base=/leafspace-test/` and `npx vite preview --base=/leafspace-test/ --port 4173 --strictPort`, then run `PLAYWRIGHT_BASE_URL=http://localhost:4173/leafspace-test/ npx playwright test pdf-decoders.test.ts --project=chromium --retries=0`. Tests require every observed decoder URL to remain below the mounted app prefix, so availability of root assets cannot mask an incorrect worker-relative URL. A deployed host must mount the whole build at its configured prefix.

Held decoder checks wait for the actual 60px bitmap before sampling colors, so a cached larger preview cannot conceal a failed small render. Custom-worker results must contain successes and zero errors. Firefox can omit dynamic worker imports from Playwright network events; worker Resource Timing supplements those events while retaining the same required local fallback URL and mounted-prefix assertions. No decoder or image-rendering errors are suppressed, and no blanket blank-page heuristic is used.

Raster-recovery tests throw once or twice from native `CanvasRenderingContext2D.drawImage` only for the selected reader/page canvas. PDF.js and React-PDF still execute their real rejection and retry paths; temporary canvases and thumbnail workers are untouched. A generated raster PDF with an internal full-page link makes native PDF layer stacking observable. Recovered screenshots precede the first pixel readback of the replacement canvas. This verifies explicit failed-raster recovery, not automatic detection of silently blank PDFs, memory-pressure diagnosis, physical-device canvas limits or the separate pending-worker teardown issue. Mobile projects establish responsive emulation; native-touch and assistive-technology hardware validation remain separate.

Deterministic UI cases additionally cover stale page/scale/size/session callbacks, repeated clicks, unmount and StrictMode, a focused Retry removed by resize, background completion that must not steal focus, and interruption of an older pinch preview. Retry does not reload Document, clear durable state, change PDF.js versions or suppress render errors.

Internal PDF links are resolved through the owning Document's public PDFDocumentProxy. Annotation metadata is captured before PDF.js renders its anchors; a reader capture handler intercepts only ordinary local destinations while external URIs, named actions, attachments, forms and optional-content actions retain PDF.js handling. Reader Documents keep a session/source/window identity; page, zoom, width, focus and raster-retry changes do not reparse the document. This does not fix the separate pending-worker teardown rejection.

Each activation owns a cancellable ticket through both named-destination and indirect-page-reference resolution. A newer link, explicit navigation (including choosing the same page), owning QuickFlip entry, retry, page/session/owner retirement or unmount permanently retires older work. Focus is returned before a departing annotation disappears only while the active visible source still owns it. Missing/invalid destinations produce dismissible local feedback; Escape from that pane dismisses the notice before global window closing. Post-pinch/swipe click suppression is checked before React capture can navigate; keyboard activation remains available.

UI tests cover synchronous retirement, away-and-back, no-op main/reference navigation, both asynchronous stages, current/stale rejection, repeated activation, StrictMode and focus ownership. Browser tests use real generated PDF annotations, worker-protocol response gates, saved-source hashing, reopen verification, same-page Home/page input, QuickFlip open/cancel/commit and a deliberate missing destination. Synthetic touch events establish gesture/click ordering across engines; they are not physical-device touch validation. Destination-coordinate/zoom interpretation remains outside this page-navigation feature.
